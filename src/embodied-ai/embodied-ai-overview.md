## 1. 什么是具身智能数据

具身智能（Embodied Intelligence）的核心是让机器人通过与物理世界交互来学习和执行任务。与纯文本或图像数据不同，具身智能数据是**多模态、时序、动作-观测对**的组合。

### 数据层级结构

```
Dataset
└── Episode（一次完整的任务执行，如"抓起方块放到目标位置"）
    └── Step（每个时间步的一帧数据）
        ├── Observation（观测）
        │   ├── RGB 图像（多相机：正面 / 侧面 / 手腕）
        │   ├── 深度图（Depth map）
        │   ├── 关节角度（Joint positions，7-DOF 机械臂 = 7维向量）
        │   ├── 末端执行器位姿（EE Pose：x, y, z, qx, qy, qz, qw）
        │   └── 夹爪状态（Gripper state：开/合/宽度）
        └── Action（动作）
            ├── 关节目标位置 / 速度 / 力矩
            ├── 末端执行器目标位姿（delta 或 absolute）
            └── 夹爪指令（开/合）
```

### 数据量级估算

| 采集频率 | 单步数据量 | 30秒 Episode | 1000 Episode 数据集 |
|---------|-----------|-------------|-------------------|
| 30 Hz | ~500KB（3相机RGB+深度） | 30×30×500KB ≈ 450MB | ~450GB |
| 10 Hz | ~200KB | 30×10×200KB ≈ 60MB | ~60GB |

## 2. 数据采集方式对比

| 方式 | 成本 | 数据质量 | 扩展性 | 代表方案 |
|------|------|---------|--------|---------|
| 真实机器人 | 极高（硬件+运维） | 最高（真实物理） | 低（一台机器一个任务） | Franka + 人工遥操作 |
| 遥操作 | 中（硬件+人力） | 高（人类示范） | 中（需要人类操作员） | ALOHA, GELLO |
| **仿真** | **低（GPU服务器）** | **中（Sim-to-Real Gap）** | **极高（并行数千环境）** | **ManiSkill, Isaac Sim** |

### 为什么建议从仿真入手

- **零硬件成本**：一台 GPU 服务器可并行运行数百个仿真环境
- **快速迭代**：修改任务参数、环境布局只需改代码
- **真值完美**：仿真中所有物理量（位置、速度、力）都是精确已知的
- **数据多样性**：可通过域随机化（Domain Randomization）生成海量变体数据

## 3. 数据存储格式

### LeRobot 格式（推荐）

HuggingFace 推出的具身数据标准，基于 Apache Parquet：

```
my_dataset/
├── meta/
│   ├── info.json          # 数据集元信息（任务描述、机器人模型、采集参数）
│   ├── episodes.jsonl     # 每个 episode 的元数据（成功/失败、长度、标签）
│   └── stats.json         # 数据统计（均值、方差，用于归一化）
├── data/
│   ├── chunk-000/
│   │   ├── episode_000000.parquet   # 单个 episode 的所有 step 数据
│   │   ├── episode_000001.parquet
│   │   └── ...
│   └── chunk-001/
│       └── ...
└── videos/
    ├── observation.images.cam_high/
    │   ├── episode_000000.mp4       # 正面相机视频
    │   └── ...
    └── observation.images.cam_wrist/
        └── ...
```

**为什么选 LeRobot：**
- 基于 Parquet，压缩率高（比原始图像节省 80%+ 存储）
- 支持流式加载（不用一次加载整个数据集）
- HuggingFace 生态（Hub 分享、在线可视化）
- 社区活跃（HuggingFace 官方维护）

### 格式对比速查

| 特性 | RLDS | LeRobot | 自定义 HDF5 |
|------|------|---------|------------|
| 压缩率 | 中 | 高（Parquet + 视频编码） | 中 |
| 流式加载 | 支持 | 支持 | 需自己实现 |
| 生态集成 | TensorFlow | HuggingFace Hub | 无 |
| 学习曲线 | 陡峭 | 平缓 | 平缓 |
| 推荐场景 | Google 内部 | 开源社区首选 | 原型验证 |

## 4. 数据清洗要点

### 4.1 异常检测清单

| 异常类型 | 检测方法 | 处理策略 |
|---------|---------|---------|
| 关节角度超限 | `angle > max_limit` 或 `angle < min_limit` | 标记为异常帧，整 episode 剔除 |
| 时间戳跳变 | `delta_t > 3 * expected_interval` | 插值补全或分段处理 |
| 末端执行器瞬移 | `|delta_pos| > 物理最大速度 × dt` | 标记异常帧 |
| 传感器噪声 | 高频抖动（低通滤波检测） | 平滑滤波 |
| 图像全黑/全白 | 像素均值 < 5 或 > 250 | 标记异常帧 |
| 物体飞出场景 | 物体位置超出工作空间范围 | 整 episode 标记为失败 |

### 4.2 Episode 质量筛选

```
清洗 Pipeline:
  原始 Episode（1000个）
    → 去除任务失败 Episode（物体掉落、超时）→ 剩余 850
    → 去除关节异常 Episode（角度超限 > 5帧）→ 剩余 820
    → 去除图像质量差的 Episode（模糊占比 > 10%）→ 剩余 780
    → 去重相似 Episode（轨迹相似度 > 0.95）→ 剩余 720
```

### 4.3 帧去重策略

- **静止帧**：连续 N 帧关节角度变化 < 阈值 → 只保留首帧
- **相似帧**：图像 SSIM > 0.98 → 采样保留（等间隔抽取）
- **无效帧**：夹爪正在运动中但物体已滑落 → 通过物体位置判断

## 5. 数据标注方案

### 5.1 标注维度

对具身智能操作数据，标注的核心是**时序分割** + **语义标签**：

| 标注维度 | 类型 | 示例 |
|---------|------|------|
| 操作阶段 | 时序分类 | 接近物体 / 抓取 / 移动 / 放置 / 归位 |
| 成功/失败 | Episode级二分类 | success / failure |
| 失败原因 | Episode级多分类 | 抓取失败 / 碰撞 / 物体滑落 / 超时 |
| 物体属性 | 帧级标签 | 物体类别、位置、姿态 |
| 抓取类型 | 帧级分类 | 顶抓 / 侧抓 / 精密抓取 |

### 5.2 标注方式对比

| 方式 | 单 episode 耗时 | 准确率 | 成本 |
|------|----------------|--------|------|
| 纯人工 | 5-15 分钟 | 95%+ | 极高 |
| VLM 自动标注 | 10-30 秒 | 70-85% | 低（API 费用） |
| 半自动（预标注+校验） | 1-3 分钟 | 90%+ | 中 |

### 5.3 VLM 自动标注 Prompt 示例

```
你是一个机器人操作数据标注专家。
以下是从机械臂操作视频中采样的 8 帧图像（按时间顺序排列）。
请判断每一帧属于哪个操作阶段，可选阶段：
- APPROACH: 机械臂正在接近目标物体
- GRASP: 夹爪正在闭合抓取物体
- LIFT: 将物体从桌面抬起
- TRANSPORT: 将物体移动到目标位置
- PLACE: 正在放置物体
- RETREAT: 机械臂离开，任务完成

请输出 JSON 格式的阶段分割结果。
```

## 6. 后端工程能力切入点

具身智能数据管线与你的后端/大数据能力高度契合：

### 6.1 标注平台后端

```
前端标注界面
    ↓ REST API
标注任务服务（你擅长的：Spring Boot + 数据库设计）
    ├── 任务分发（Round-Robin / 基于负载）
    ├── 多人标注一致性校验（Fleiss' Kappa）
    └── 标注数据版本管理
```

### 6.2 数据 Pipeline 调度

你的线程池经验直接适用：
- **背压控制**：仿真采集速度快于清洗速度 → 需要用有界队列 + 拒绝策略
- **并行处理**：多个 episode 并行清洗，ThreadPoolExecutor 调优
- **异常处理**：单个 episode 清洗失败不影响全局（类似 ThreadPoolFailover 模式）

### 6.3 存储与检索

- **海量小文件存储**：MinIO / S3（百万级 episode 的视频帧）
- **元数据检索**：基于 episode 标签的 ElasticSearch 索引
- **数据版本管理**：类似 DVC 的版本控制，跟踪数据变更历史

## 面试高频问答

### Q1: 具身智能数据与 CV/NLP 数据有什么本质区别？

**三句话回答：**
1. **多模态 + 时序**：包含 RGB、深度、关节状态、力觉，且是连续时间序列
2. **动作-观测闭环**：数据包含 action（动作指令），每一帧的 action 决定下一帧的 observation
3. **物理约束**：数据必须符合物理规律（速度连续、无瞬移），清洗时需要物理感知

### Q2: 为什么仿真数据可以用于训练真实机器人？

**关键词：Domain Randomization（域随机化）**

通过在仿真中随机化视觉（光照、纹理、相机位置）和物理参数（摩擦系数、物体质量），让模型学会"忽略"无关特征，提取任务本质。相当于"在仿真中见过足够多的变化，在真实世界中就不会被没见过的变化难住"。

### Q3: 数据清洗对下游训练影响有多大？

**结论：清洗不当直接导致策略无法迁移到真实机器人。**

典型案例：
- 未过滤失败 episode → 模型学到错误动作
- 未检测关节异常 → 模型学到物理上不可能的动作
- 未去重相似帧 → 数据偏向静止状态，模型变"懒"
