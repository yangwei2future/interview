# 意图识别模块（Intent Recognition）

## 职责

只做一件事：**判断问题复杂度，决定走哪条路。**

不拆解，不规划，不做任何实际查询。

## 输入

```
String query：用户的自然语言问题
```

示例：
```
"2026年理想L6的销量是多少？"
"为什么理想L6销量下降了？"
"L6和L7哪个增长更快？"
```

## 输出

```java
public class IntentResult {
    /** 规划类型 */
    private PlanType planType;

    /** 判断理由（调试/日志用，非必须） */
    private String reasoning;
}

public enum PlanType {
    /** 一次性规划：目标明确，不需要中间结果来修正方向 */
    SINGLE_TURN,

    /** 动态规划：需要先探索，根据中间结果决定下一步 */
    MULTI_TURN
}
```

## 判断标准

```
不是判断"一条SQL能不能搞定"
而是判断"所需信息在开始之前是否已全部确定"

全部确定 → SINGLE_TURN
   不需要中间结果来修正方向
   你知道该查哪些数据，只是不知道在哪个表、哪个字段
   例："XX销量多少"、"昨天GMV"

部分未知 → MULTI_TURN
   需要先拿到中间结果，再看下一步做什么
   例："为什么XX下降"（先看趋势→再钻原因）
   例："哪个增长最快"（先各查一遍→再比较排序）
```

## 输入 → 输出示例

```
输入："2026年理想L6的销量是多少？"
输出：
  plan_type: SINGLE_TURN
  reasoning: "目标(销量)、对象(L6)、时间(2026)已全部确定，
              不需要中间结果修正方向"

输入："理想L6和L7哪个增长更快？"
输出：
  plan_type: MULTI_TURN
  reasoning: "涉及对比+增长率计算，需要先分别查询再做比较"
```

## 实现方式

意图识别不是一段单独的代码，而是 **LLM 在 System Prompt 约束下的分类判断**。

```markdown
# System Prompt 片段

你是一个数据分析 Agent。根据用户问题判断处理路径：

## SINGLE_TURN（一次性规划）
以下情况走此路径：
- 问题目标、对象、时间范围全部明确
- 你不需要中间结果来修正后续方向
- 示例："查XX销量"、"昨天GMV多少"、"上个月订单量"

## MULTI_TURN（动态规划）
以下情况走此路径：
- 问题目标模糊，需要先探索再确定
- 涉及多实体对比，且对比结果会影响下一步
- 涉及因果分析（"为什么"类问题）
- 示例："为什么XX下降"、"哪个增长最快"、"对比A和B的趋势"

请对用户问题返回 JSON：
{"plan_type": "SINGLE_TURN" | "MULTI_TURN", "reasoning": "..."}
```
